# Owner objective installation contract

Status: engineering; production activation remains gated.

Host the existing canonical Universal Plan service separately from Ticket Core.
Move its existing SQLite database intact into dedicated component state and
retain a compatibility link. Preserve existing decisions, audit, claims and all
newer decisions on rollback. Checkpoint, exclusive access and a Root before-image
are required before migration.

Mount current authority, identity bindings and gateway public keys read-only.
Keep subordinate execution contexts and the execution ledger in component state.
Mount no Owner signing key, business provider credential, Docker socket or
read/write Core authority directory.

A separate installed Root path/service accepts only typed requests. Root keeps
its enrolled exact plan, original signed decision, one-use native claims and
independent readbacks in protected storage. Root sends the reviewed objective
card itself through the existing Jason bot. A caller cannot assert delivery or
substitute its own presentation for the privileged review.

Initial registration is the documentation restore/verify pair plus a separate
nonexecuting acceptance test. Root independently checks the licensed Owner,
service, six exact live grants, source/CI, ordered actions, artifacts, policy,
protected health, freeze and hold. Additional privileged handlers need review;
this pilot cannot authorize arbitrary releases or replace financial/core gates.

Initial governed activation explicitly covers trusted code/configuration,
typed spool and two Root units, intact canonical database migration, six narrow
grants, the isolated component, the gateway callback-route addition, exact drift
policy additions with one retained rollback, independent health and native Root
LKG recapture. Preserve accepted Stage E code, shared Root release worker,
Runtime, MCP, Ticket Core, freeze, hold and Engineering Owner Pause.

Run full Root preflight before the bootstrap Owner prompt, and repeat it under
the host lock afterward. On failure restore exact own changes and keep private
evidence. Acceptance additionally requires real Teams Deny and Approve decisions,
the actual SDK message linkage and verified native completion.
