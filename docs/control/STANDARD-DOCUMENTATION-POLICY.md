# Project Jason — Standard Documentation Policy

**Status:** Active canonical terminology and policy entry point  
**Owner:** Jason Architecture Authority  
**Governing standard:** `docs/standards/J-404-Documentation-Governance-and-Continuity.md`

## Canonical name

The complete Jason documentation-governance, continuity, reconstruction, and reusable-construction framework shall be referred to as the **Standard Documentation Policy**.

Future human and AI sessions should use that term consistently rather than inventing alternate labels for the same framework.

## What the Standard Documentation Policy includes

The Standard Documentation Policy is implemented through the governed documentation control plane and its supporting controls, including:

- `docs/standards/J-404-Documentation-Governance-and-Continuity.md` — governing documentation standard;
- `docs/control/JASON-FUNDAMENTALS.md` — mandatory fundamentals/reconstruction baseline;
- `docs/control/CURRENT.md` — canonical current resume point;
- `docs/control/EXTENSION-CONSTRUCTION-MAP.md` — reusable component construction map;
- `docs/control/DOCUMENTATION-REGISTER.md` — authoritative knowledge-location register;
- `docs/control/HOW-TO-DOCUMENT-JASON.md` — documentation authoring and maintenance procedure;
- `docs/control/IMPLEMENTATION-DOCUMENTATION-INDEX.md` — implementation-local documentation index;
- documentation templates and handoff controls under `docs/control/`;
- documentation validation and CI enforcement; and
- the System Registry boundary that keeps current operational topology in structured operational truth rather than narrative memory.

This file is an entry point and canonical terminology record. It does not replace or override J-404, the Constitution, approved governance, canonical architecture, System Registry authority, or other higher-authority records.

## Governing intent

The Standard Documentation Policy exists so Jason can move forward without repeatedly rediscovering fundamentals, wiring, component-construction patterns, governance boundaries, operational procedures, or prior decisions.

A workstream is not documentation-complete when a future competent human or AI would need chat history, personal memory, or code archaeology to understand how to continue the work safely or create another governed component of the same class.

## Usage

When discussing Jason documentation governance in future sessions, use **Standard Documentation Policy** as the umbrella name. Refer to J-404 or the specific control document when the exact governing rule or procedure matters.
