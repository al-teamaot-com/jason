## Source-only bootstrap bundle and narrow privileged path

`tools/catalog_scoped_root_bootstrap_packet.py` builds an immutable source-only packet from protected Git blobs. It includes the 17 previously reviewed catalog installer files, the root transaction/installed bootstrap source and its pure plan dependencies, and two **bootstrap recovery systemd units**. It emits a one-time root staging script and a source manifest with exact SHA256 for every path. Source-only staging is limited to a new operator-owned temporary directory; no production writes or elevation occur in the builder.

The generated `ROOT_STAGE_AND_AUTHENTICATE_ONCE.sh` should only be executed from a **root-owned verified copy** by an Owner who has authenticated sudo/root at the terminal. Its only preparatory writes are fixed root-owned bootstrap source under `/usr/local/lib/jason/catalog-root-bootstrap` and one root-owned bootstrap trust policy at `/etc/jason-owner-release/catalog-scoped-root-bootstrap-trust.json`. It hashes each file before/after copying. It then runs installed Python with `-I`, `--check-only` first and `--execute` only after the read-only checks pass; the latter requires new Entra Owner sign-in and exact terminal confirmation. Never execute a mutable operator-owned shell script directly with root privilege, and never provide a sudo password/MFA token in ChatGPT.

Installed `/usr/local/lib/jason/catalog-root-bootstrap/tools/catalog_scoped_root_install_native.py` refuses execution from a developer checkout, non-root user, non-isolated interpreter or root bundle that differs from the protected SHA and exact policy. It verifies the original root worker, root-only current release trust, protected source and all **ten** required GitHub CI names from the independently verified read-only admission, source/image and rollback evidence, original freeze and protected Docker container identities. Only root-trusted production code acquires the existing `production-transaction.lock`.

## Installation and bounded crash recovery

Once root-trusted code verifies the fresh Owner identity, it journals one exact intent and durably consumes the one-use approval before any root installation. It backs up original worker bytes and freeze first. It then installs and activates `jason-catalog-root-bootstrap-recovery.timer` **before changing the existing root worker**. The timer runs a root-owned `--recover` process on a bounded cadence and shares the exact production lock: while an authorized installer owns the lock the watchdog defers without touching production; if the installer crashes it can restore the original worker, units and freeze. Recovery never uses the Owner approval to promote again. A crash before approval consumption is verified as no-mutation if the old root worker, freeze and all protected containers are unchanged. Unexpected partial mutations/missing Owner consumption open the protected breaker; unverified rollback must not be repeatedly auto-tried.

The actual scoped root installation changes only the 17 pinned root-file destinations, approved catalog trust policy and bounded recovery unit/timer. Source files are installed atomically and the original root worker is copied **last**; any failure restores the exact prior worker and removes only source-hash-matched newly installed code/units. The install must independently read back every digest, both active recovery timers, all five protected container identities/start times/images and the original frozen bytes. Root audit and consumed approval ledger remain protected.

The one-time bootstrap recovery timer remains active in a read-only monitoring role after successful root installation, and is disabled/removed if the installation is rolled back. The source-only bootstrap is **not a production root installer until a verified root Owner terminal stages and executes it with fresh exact consent**.
