# Stage E operational closure after native acceptance

Native cutover acceptance and continuous operational acceptance are separate gates. Disabled legacy trigger files still appear in systemd's installed inventory. A monitor must also execute the accepted watchdog, and its engineering source must satisfy the accepted controlplane convergence rule.

The bounded closure utility runs after an existing signed native Stage E receipt is accepted. It independently verifies that historical signature, the root-owned acceptance marker and policy, the complete unchanged accepted code tree, current source/CI, exact six old/new states, protected peer identities, freeze, hold, pause, and the prior runtime fingerprint. Only the exact retired-file inventory drift and its failed drift-watchdog consequence are admissible.

After one separately authenticated exact Owner decision, it:

1. Seals before-images of the six disabled legacy trigger files in a root-private journal and removes only those exact files. Legacy service implementations and accepted release code stay unchanged.
2. Adds a user-service drop-in that executes the already accepted watchdog copy and preserves its original immutable helper source.
3. Repoints the engineering source link to a separate, fully prepared clean checkout at the accepted Stage E revision. The prior checkout and runtime source pointer stay unchanged.
4. Reloads systemd metadata, verifies the replacement controls and actual watchdog convergence, and refreshes drift using the existing production watchdog.
5. Requests the existing root transition worker's same-runtime last-known-good recapture. Every manifest field except observation time and the exact accepted scheduling map must remain equal. The root worker independently verifies clean drift, the existing approved runtime release record, and live production health before closing the breaker.

No protected container is restarted. Provider authority, images, resource limits, accepted policy, accepted marker, immutable native code, freeze, hold and engineering pause are unchanged. No caller-supplied PASS or direct protected-control JSON replacement is accepted.

The preflight mode emits the complete concrete scope without requesting authority or mutating production. The apply mode repeats that inspection under original host locks after Owner authentication. A consumed closure attempt cannot be retried implicitly. Failure during file preparation restores only exact owned before-images; failure during subsequent verification retains durable evidence and requires governed recovery.

Regression coverage proves that unrelated runtime or scheduling changes deny recapture, preflight and Owner denial cannot reach mutation, archived file identities survive exact rollback, and foreign file replacements are not overwritten. Disposable UID0 tests exercise real ownership and file operations with synthetic paths. Actual continuous post-install verification remains required.
